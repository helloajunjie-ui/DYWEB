# 抖音直播场控中枢 · 设计文档（v0.1 原型）

> 项目代号：DYweb　｜　目录：`E:\DYweb`　｜　技术栈：Go 1.22（后端）＋ Vue 3 + Vite（控制台/舞台层）

---

## 0. 一句话定位

**本地场控中枢**：不逆向平台协议、不碰直播伴侣内部，被动接收第三方弹幕工具推来的直播间事件，在本地做「解析 → 规则 → 动作」三段闭环，把事件变成声音、画面、硬件和 AI 话术。

```
第三方弹幕工具 / 直播伴侣插件
        │  HTTP POST / WS 推 JSON
        ▼
┌────────────────────────────────────────┐
│  Ingest  接入层   :9101 /push /ws/ingest │
├────────────────────────────────────────┤
│  Normalize 归一化（字段映射 + 类型别名）    │
├────────────────────────────────────────┤
│  Rules  规则引擎（关键词/礼物/金额/连击/冷却）│
├────────────────────────────────────────┤
│  Actions 动作层（可插拔）                  │
│   tts · sound · effect · banner          │
│   webhook · llm · hotkey · [obs] [vtube] │
└────────────────────────────────────────┘
        │              │            │
        ▼              ▼            ▼
   Overlay 舞台层   本机扬声器    硬件/外部服务
  (OBS浏览器源)      (SAPI TTS)   (ESP32/灯控/OBS)
```

设计原则：

1. **协议无关**：任何第三方工具，只要能 POST 一个 JSON 到本机端口，就能接。字段不匹配时改 `config.json` 的映射表，不改代码。
2. **动作可插拔**：新增一种反馈 = 新增一个 `Action.Type` 分支，规则配置里直接写，不动引擎。
3. **一切可调试**：控制台内置模拟推送，任何规则不接真实直播间也能验；每条命中都留 trace。
4. **单机可离线**：TTS 走 Windows SAPI（本机发声，不联网）、特效走本地页面、无云端依赖。唯一联网项是 LLM 话术（可关）。

## 1. 架构分层

| 层 | 职责 | 代码位置 |
|---|---|---|
| Ingest | 收 HTTP / WS 原始 JSON，支持单条与数组 | `server/ingest.go` |
| Normalize | raw → `Event`，字段映射、类型推断、单位归一 | `server/normalize.go` |
| Rules | 匹配、连击累计、冷却、优先级、命中 trace | `server/rules.go` |
| Actions | 各动作执行器 + 异步队列 | `server/actions.go`、`tts.go`、`hotkey_windows.go` |
| Hub | WS 广播中心（console / overlay 两类客户端） | `server/hub.go` |
| Store | 事件环缓冲、统计、观众画像 | `server/store.go` |
| API | REST 控制面 + 静态资源（embed 前端） | `server/api.go`、`main.go` |
| Console | 控制台：总览 / 规则 / 画像 / 调试台 / 设置 | `web/src/views/*` |
| Overlay | 舞台层：全屏特效 + 大字横幅，OBS 浏览器源 | `web/src/overlay/*` |

单进程、单端口 `9101`：`/` 控制台、`/overlay` 舞台层、`/api/*` 控制面、`/push` 与 `/ws/ingest` 数据入口、`/sfx/*` 音效文件。

前端构建产物 `web/dist` 通过 `//go:embed` 打进 exe，分发就一个文件 + `sfx/` + `data/`。

## 2. 数据接入协议

### 2.1 三种入口

| 方式 | 地址 | 说明 |
|---|---|---|
| HTTP POST | `http://127.0.0.1:9101/push` | body 为 JSON 对象或数组，第三方工具最常用 |
| HTTP GET | `http://127.0.0.1:9101/push?data={json}` | 只支持拼 URL 的工具（URL 编码） |
| WebSocket | `ws://127.0.0.1:9101/ws/ingest` | 支持长连接推送的工具 |

监听 `0.0.0.0`，所以同局域网的另一台机器（比如跑游戏的机器）也能推。

### 2.2 事件模型（归一化后）

```json
{
  "id": 1287,
  "ts": 1762400000000,
  "type": "gift",                 // danmaku|gift|like|enter|follow|unknown
  "user": "素月",
  "userId": "8821",
  "avatar": "https://...",
  "level": 12,                    // 账号等级
  "guardLevel": 2,                // 星守护等级 1~3
  "fansClubLevel": 8,             // 粉丝团等级（0=未知/未加团）
  "text": "",                     // 弹幕原文
  "giftName": "玫瑰",
  "giftCount": 10,
  "giftValue": 1,                 // 单价（抖币）
  "total": 10,
  "raw": "{...原始JSON...}",
  "hitRules": ["大礼物感谢"],
  "fanNote": "上周过生日，爱听《晴天》",
  "isRegular": true
}
```

### 2.3 字段映射

`config.json` 里 `mapping` 是「逻辑字段 → 候选路径数组」，路径支持点号取嵌套，命中即取：

```json
"mapping": {
  "user":   ["user", "nickname", "data.user.nickname", "Data.User.NickName"],
  "text":   ["text", "content", "msg", "data.content"],
  "giftName": ["giftName", "gift", "data.gift.name"],
  "fansClubLevel": ["fansClubLevel", "fansclub_level", "fanClubLevel", "data.user.fansClubInfo.level"]
}
```

查找顺序：精确路径 → 同级 key 忽略大小写 → 若首段未命中，自动下沉到 `data` / `Data` 容器。这样市面上大多数工具（字段叫 `nickname` / `nick_name` / `uname`，包在 `data` 里或不包）都能不改代码接上。

### 2.4 类型判定

先查 `typeAliases`（如 `WebcastChatMessage` → danmaku）；查不到再用内容推断：有 `giftName` 判 gift，有 `text` 判 danmaku，否则 unknown。

## 3. 规则模型

```json
{
  "id": "r_fireworks",
  "name": "大礼物烟花",
  "enabled": true,
  "match": {
    "types": ["gift"],
    "giftNames": ["嘉年华", "火箭"],
    "minValue": 0,
    "minCount": 1,
    "minLevel": 0,
    "userName": "",
    "comboWithinMs": 0,
    "onlyRegular": false,
    "regularMin": 5
  },
  "actions": [
    { "type": "tts",    "template": "感谢{user}送的{gift}×{count}，老板大气！" },
    { "type": "effect", "preset": "fireworks", "durationMs": 6000 },
    { "type": "sound",  "file": "boom.wav", "volume": 0.8 },
    { "type": "webhook","url": "http://192.168.1.50/relay", "method": "POST",
      "template": "{\"ch\":1,\"action\":\"pulse\",\"ms\":800}" }
  ],
  "cooldownMs": 1000
  "priority": 10
}
```

匹配语义（全部 AND，空值视为不限）：

| 字段 | 语义 |
|---|---|
| `types` | 事件类型白名单 |
| `keyword` + `keywordMode` | 弹幕文本 `contains` / `equals` / `prefix` / `regex` |
| `giftNames` | 礼物名包含匹配（任一命中） |
| `minValue` / `minCount` | 礼物单价 / 数量下限 |
| `minLevel` | 观众等级下限 |
| `userName` | 指定观众（昵称包含） |
| `comboWithinMs` | 连击窗口：同人同礼物在窗口内累加，`{combo}` 取累计数，超窗重置 |
| `onlyRegular` / `regularMin` | 老粉专属：该观众累计互动 ≥ N 次 |

**冷却**：`cooldownMs` 内同规则不再触发（按规则计，不按观众），防刷屏。
**优先级**：`priority` 大的先执行；命中后仍允许后续规则继续（不做短路，方便「感谢 + 特效 + 灯光」拆成三条规则维护）。

### 模板变量

`{user}` `{text}` `{gift}` `{count}` `{value}` `{total}` `{level}` `{guard}` `{combo}` `{fanNote}` `{time}`

> `{fanNote}` 仍可用，但**默认模板已移除**：备注定位是主播筛人用的，不念。

### 3.1 进场欢迎门槛（WelcomeConfig）

主播只欢迎「三高」：高等级 / 高粉丝团 / 高消费。三项**各自独立开关**，门槛自定，可全关。

```json
"welcome": {
  "enabled": true,     // 总开关；关=谁都欢迎
  "levelOn": true,     // 看账号等级
  "fansOn": false,     // 看粉丝团等级
  "valueOn": false,    // 看累计消费
  "minLevel": 30,
  "minFans": 5,
  "minValue": 100      // 抖币
}
```

判定（`app.go` 的 `HandleEvent`，仅 `type == "enter"`）：

1. 总开关关 → 直接放行；
2. 三项都关 → 放行（谁都欢迎，避免把所有人静默挡掉）；
3. 否则取 `store.FanOf(user, userID)` 的历史画像，`levelOn && Level ≥ minLevel`、`fansOn && FansClubLevel ≥ minFans`、`valueOn && GiftValue ≥ minValue` 三者取**或**；
4. 不达标：写一条 trace（`Rule=欢迎门槛, Action=skip, Msg=未达欢迎门槛，跳过欢迎`）然后 `return`，不播报、不出横幅。

兼容：老配置只有阈值没有分项开关时，`config.go` 加载阶段按「阈值 > 0」自动打开对应项。

### 3.2 直播定位（LiveMode）：两个轴，四种组合

定位不是三个并列类型，而是 **讲什么 × 有没有人**：

| ID | 按钮 | 讲什么 | 有人吗 | 默认分类 | 默认场景 |
|---|---|---|---|---|---|
| `fun` | 娱乐 | 娱乐（聊天/整活/游戏） | 真人在 | `keep` | `fun` |
| `fun_auto` | 无人娱乐 | 娱乐（游戏轮换 + AI 聊天） | 无人 | `interact` | `fun` |
| `ecom` | 电商 | 电商（讲品/算账/避坑） | 真人在 | `push` | `ecom` |
| `ecom_auto` | 无人电商 | 电商（循环安利/自动答疑） | 无人 | `push` | `ecom` |

- `LiveMode{ID,Short,Name,Desc,Focus,Script,Scene,Rec,Tips}`：`Script` → 话术库默认分类，`Scene` → 默认场景，`Rec` → 功能中心「本模式推荐」，`Tips` → 总览三条提示。
- **场景只表达内容**（`""` / `fun` / `ecom`）；「无人」是形态，不单独占场景。无人专属话术按内容归到 `fun` 或 `ecom`（无人娱乐 5 条、无人电商 4 条）。
- `ModeScene(mode)`：供后端 AI 参考话术做场景隔离（`app.go` 取 `ModeScene(cfg.Mode)`）。
- 迁移：老配置 `mode == "auto"`（把无人当第三种类型）→ `fun_auto`；未知值回落 `fun`。

### 3.3 分场景 AI 人设（LLM.Prompts）

同一套 LLM 人设在娱乐场会写成卖货腔，所以人设按定位分开：

```
LLMConfig{
  System  string            // 通用兜底，只在某场景一个字都没写时用
  Prompts map[string]string // fun / fun_auto / ecom / ecom_auto
}
```

- `PromptFor(mode)`：取该定位的人设，空则回落 `System`。
- 调用侧：规则 `llm` 动作走 `ChatMode(cfg.Mode)`；话术库「AI 帮我想一句」按当前定位（若在别的场景临时问，按内容场景换）；商品推荐话术固定走电商那套（当前定位是无人电商就用 `ecom_auto`）。
- 游戏类调用（转盘词条、猜数字毒舌、抓叛徒）保留 `ChatWith`，不叠直播人设，避免「只输出词条」的硬约束被口语人设冲掉。
- 落盘兼容：老配置无 `Prompts` 时按 `defaultPrompts()` 逐键补齐；前端只回传部分键时，`Set()` 合并保留其它场景，不整份冲掉。

### 3.4 直播状态探测（`/api/live/status`）

边界：**不读伴侣内部、不逆向它的接口**，只用本机可观测信号推断：

| 信号 | 取法 |
|---|---|
| 伴侣在不在跑 | `Get-Process 直播伴侣` 且有主窗口，取 PID/窗口标题 |
| 是不是在推流 | 两次采样 `Win32_PerfRawData_PerfProc_Process`（所有「直播伴侣*」进程的 `IOWriteBytesPersec + IOOtherBytesPersec` 增量 ÷ 间隔），≥60KB/s 判为在播 |
| 数据有没有在流 | `/push` 或 `/ws/ingest` 成功写入后记 `lastIngest`，≤90 秒算“在流动” |

三态：`living`（在播）/ `open`（伴侣开着没开播）/ `off`（没检测到）。5 秒缓存，避免反复起 PowerShell。结果只作提示，不能当作抖音后台的权威状态。

## 4. 动作层

| Type | 作用 | 通道 | 本轮状态 |
|---|---|---|---|
| `tts` | 念话术 | 本机 SAPI（异步队列，可切 overlay 朗读） | ✅ 实现 |
| `sound` | 播音效/BGM | 本机 WAV 直放 + overlay WebAudio 双通道 | ✅ 实现 |
| `effect` | 画面特效（烟花/爱心雨/流星/彩带/抖动/聚光） | WS → overlay canvas | ✅ 实现 |
| `banner` | 大字感谢横幅（含头像/礼物/数量） | WS → overlay DOM | ✅ 实现 |
| `webhook` | 硬件/外部服务联动（灯光、机械、串口网关、IFTTT） | HTTP 出站 | ✅ 实现 |
| `llm` | AI 生成话术（OpenAI 兼容接口），结果可直接接 tts | HTTP 出站 + 队列 | ✅ 实现 |
| `hotkey` | 模拟按键整蛊（Ctrl+Space / F5 / WASD 组合） | Win32 SendInput | ✅ 实现 |
| `obs` | OBS 换场景 / 开关录制推流 | obs-websocket v5 | ⬜ 预留 |
| `vtube` | VTube Studio 表情 / 嘴型 | VTS WebSocket API | ⬜ 预留 |
| `serial` | 串口直连单片机 | COM 口 | ⬜ 预留 |

**执行模型**：每条规则命中 → 动作按序派发到独立 goroutine，互不阻塞；TTS 与 LLM 走串行队列（避免多句叠音）。每个动作结果都回写一条 `trace` 到控制台，失败不静默。

## 6. 控制台与舞台层

### 6.1 控制台（`/`）

| 页 | 内容 |
|---|---|
| 总览 | 接收状态（最后事件时间、事件数/分）、今日统计、送礼榜、实时事件流 |
| 功能中心 | 七组人话分类（① 接数据 / ② 说话：AI 与语音 / ③ 画面：礼物特效 / ④ 玩法：抽奖和整活 / ⑤ 声音：音效与提示 / ⑥ 外设：灯光和按键 / ⑦ 后台：自动修复）；模块开关 + 「试一下」 + 「已开 X / 可用 Y」 |
| 规则 | 规则列表 CRUD、启停、命中次数；顶部「进场欢迎门槛」卡（三项独立开关 + 自动保存） |
| 礼物库 | 294 条内置价目、搜索、批量粘贴导入、增删改（自动保存） |
| 话术库 | 双层筛选：场景（通用/娱乐/卖货，跟随当前定位默认切）→ 分类（留人/促单/互动/感谢/冷场/下播）；念一遍、AI 帮想一句（只检索当前场景 + 通用）；**任意一条可编辑**：内置改动写成 `scripts_edits.json` 覆盖项（`Edited` 标记 + 可还原），自定义改动直接写 `scripts.json` |
| 产品库 | 商品资料、主推开关、AI 推荐话术（自动保存） |
| 观众画像 | 账号等级 / 粉丝团等级两列、互动/礼物/消费、备注历史、搜索 + 只看有备注的 筛选 |
| 调试台 | 模拟推送（手填事件或贴原始 JSON，含账号等级 / 粉丝团等级）、特效/横幅手动触发、TTS 试念、按键测试、Webhook 测试 |
| 设置 | 三页签向导：🤖 让 AI 写台词 / 🔊 语音播报 / 🧰 基础与对接（端口、字段映射、音效目录、横幅时长），改动自动保存 |

### 6.2 舞台层（`/overlay`）

- 透明背景全屏页，专供 OBS「浏览器源」（1920×1080）。
- canvas 粒子层：烟花、爱心雨、流星、彩带；DOM 层：大字横幅、进场提示。
- 收到 `effect` / `banner` 指令即播放，独立队列，不互相打断；支持手动预览模式（控制台开 `/overlay?preview=1` 点击触发）。
- **转盘**：canvas 自绘的彩色玻璃盘（扇区 0.62 白 / 0.12 白 / 原色 / 0.25 黑四层叠加，8px 铅条分隔，金色金属外环 + 镜面高光），文字白字黑描边；不用第三方转盘库，旧 SVG 版已废弃。
- 玩法层：转盘、猜数字（区间 + 猜大/猜小回显）、名字抽奖（取观众名单）。
- 音频：首次需点一下「启用声音」（浏览器自动播放限制）；OBS 浏览器源勾选「控制音频」即可。

### 6.3 手机中控台（`/panel`）

同局域网手机打开 `http://<电脑IP>:9101/panel`，五个大按钮（转盘 / 猜数字 / 名字抽奖 / AI 抓叛徒 / 清屏）+ 头部「播报 开/关」（写回 `config.tts.enabled`）。词条、转速、猜数字范围、抽奖人数存 localStorage。

## 7. 数据与存储

```
data/
  config.json   端口、字段映射、TTS、LLM（**不含 apiKey 明文**）、welcome（欢迎门槛）
  secret.dat    API Key 的 DPAPI 密文本机存储（同机同账户才能解开）
  rules.json    规则集
  fans.json     观众画像（含备注历史）
  gifts.json    礼物价目
  products.json 产品库
  modules.json  功能开关
```

**密钥存储**：`llm.apiKey` 不落进 `config.json`。首次加载时若旧配置里还是明文，会立即加密写入 `secret.dat` 并清空 `config.json` 里的字段（自动迁移）；`GET /api/config` 永远返回空 Key，只带 `apiKeySaved:true`。保存时前端传空表示「沿用已保存的那把」，不会误清空。`secret.dat` 用 Windows DPAPI（`CryptProtectData`，`CRYPTPROTECT_UI_FORBIDDEN`），绑定当前机器与账户，拷走文件无法解密。

`fans.json` 单条记录：

```json
{
  "key": "8821", "name": "素月", "level": 32, "fansClubLevel": 8, "fansClub": true,
  "msgCount": 12, "giftCount": 3, "giftValue": 6000,
  "firstSeen": 1762400000000, "lastSeen": 1762500000000,
  "note": "上周买过，老客",
  "notes": [{ "ts": 1762500000123, "text": "爱问价，先推T恤" }, { "ts": 1762500000456, "text": "上周买过，老客" }],
  "tags": ["打工人"], "regular": true

```

备注是**追加式历史**（`notes`，保留最近 20 条），`note` 只存最后一条便于列表显示；写备注不会覆盖旧内容。

事件流只留内存环缓冲（300 条），不落库——直播场景要的是即时性，历史统计在内存里累加即可。需要留档时再加按天 JSONL 落盘（P1）。

## 11. 风险与边界

1. **协议稳定性**：第三方工具字段随时会改，所以映射表外置；工具升级后先在调试台贴一条真实 JSON 验映射。
2. **平台规则**：自动化交互（自动讲解商品、模拟点击）涉及平台风控，属独立模块，默认不启用，且需人工值守。
3. **按键模拟**：对反作弊游戏无效甚至可能被判异常，只建议用于非竞技、非反作弊场景。
4. **隐私**：观众画像、弹幕原文只存本地 `data/`，不上传；接入 LLM 时只送出必要文本，配置里可整体关闭。
5. **TTS 版权**：音色克隆仅限本人声音，商用前确认授权。

## 12. 玩法扩展层（P1.5 起）

overlay 不只放「一段播完就没」的特效，而是升级成一个**常驻的透明舞台**——有物理、有状态、有账本。

### 12.1 物理挂件（Matter.js）

- 在 overlay 里叠加一个不可见的 2D 物理世界：屏幕边界为墙，主播人像轮廓位置放一组**隐形刚体碰撞箱**（用摄像头画面大致区域标定，或用 MediaPipe 人像分割求轮廓简化多边形）。
- 礼物事件 → `spawn` 指令：掉落一个带质量的刚体（爱心=轻、小弹跳；跑车/火箭=重、大冲量）。
- 效果即物理结果：轻的会砸在肩头弹开、沿地面滚落堆积；重的会把堆积的轻体全部撞飞（引擎里天然产生，不需要额外动画）。
- 计数与清理：刚体上限 60 个，超出按 FIFO 销毁，防内存与帧率塌方；静置超过 30s 的轻体自动淡出（避免画面被爱心占满）。
- 落地实现：`overlay` 里引入 `matter.js` 单文件（本地打包，不依赖 CDN），事件 `{preset:"physicsDrop", item:"heart|car|rocket", power:1|10|100}`。

### 12.2 多模态视觉闭环（P2）

- 链路：定时/触发截帧（OBS 或摄像头抓帧）→ 本地 VLM 或云端多模态接口 → 结构化点评（穿搭/表情/物品）→ 走 `tts` 播报 + `banner` 上屏。
- 权限：**只在主播本人授权、且画面中只有主播本人**时启用；不处理观众画面，不做人脸身份识别，只做「画面元素描述」。
- 涂鸦/贴纸：MediaPipe 取 468 个面部特征点 → 在 overlay 上按点位贴动态贴纸（胡子/眼镜/耳朵），30 秒自动消退。**不上传画面、不做换脸**，避免肖像与深度伪造风险。

### 12.3 博弈类 mini-game

统一用一个「玩法状态机」承载，状态由后端持有（前端只渲染），掉线重连不丢：

| 玩法 | 状态字段 | 触发 |
|---|---|---|
| 推币机 | 池中金币、边缘金币、被推落计数 | 小礼物落币、大礼物落锤；落币到阈值 → 彩蛋 |
| 阵营拔河 | 红/蓝能量、领先方、持续时长 | 弹幕/礼物加权进能量；归零侧获胜 → 全屏占领 |
| 宝箱能量条 | 当前能量、目标值、倒计时、开奖记录 | 弹幕 +1、礼物 +50；满 → 券雨 + 中奖播报 |
| 木鱼功德 | 累计功德、今日榜 | 「扣1」+1，礼物 +N；飘字「功德+1」 |

接口：`GET /api/game/:id/state`、`POST /api/game/:id/reset`，overlay 通过 WS 收 `game` 帧增量。数据落 `data/game.json`，重启不归零。

### 12.4 空间音频（HRTF）

- overlay 用 Web Audio 的 `PannerNode` + `HRH` 模型：声音资产声明 `{file, from:[x,y], to:[x,y], ms}`，播放时 pan 值随时间从起点插值到终点，形成「从左耳跑到右耳」。
- 只对耳机观众有意义，控制台里给一个「耳机模式」开关，默认关（避免音箱场景听感怪异）。

### 12.5 IoT 实体联动

- 已有 `webhook` 动作即覆盖 80% 场景（ESP32/继电器/树莓派网关都是收 HTTP）。
- 直连适配器（P3）：飞利浦 Hue（本地桥 `PUT /api/<user>/lights/<id>/state`）、米家（走米家开放平台 token）。
- `Web Serial` 只适用于主播本机的 overlay 页面，直播间浏览器源拿不到串口权限，所以串口设备走「本机小网关 + webhook」，不要指望页面直连 COM。

## 13. 无人直播：稳定性工程（本轮就做）

无人值守意味着**没人帮你刷新页面**，所以稳定性是第一需求，不是加分项。

### 13.1 特效合并 / 防刷（Anti-Spam）

不做「收 100 个爱心就放 100 次动画」，做**窗口聚合 + 强度分级**：

```
每个 (preset, 目标) 维护一个 1s 聚合桶：
  收到事件 → 计数 + 权重(礼物按数量/价值加权)
  窗口结束 → 只派发 1 次特效，附带 strength = 聚合量
前端按 strength 映射表现：
  strength < 10     → 单体特效
  10 ≤ strength<50  → 小型雨
  50 ≤ strength<200 → 暴雨 + 轻微画面抖动
  ≥200              → 豪华版（全屏 + 音效 + 横幅「全屏爱心来自 XX」）
```

引擎里由 `merge.go` 的 `Merger` 实现，规则动作加 `merge: true` 即生效；未开启合并的动作（如感谢 TTS）仍逐条执行，但 vocie 队列自带去重（2 秒内同文案不重念）。
硬上限：任何动作队列长度超过 200 直接丢弃并记一笔 `dropped`，保证不因为刷屏把进程拖死。

### 13.2 前端自愈与护栏

| 风险 | 措施 |
|---|---|
| 动画异常/依赖加载失败 | 每个特效 `try/catch` 包裹，失败即跳过本帧不重试；连续 N 次失败自动降级为纯文字模式 |
| 内存泄漏 | 粒子/刚体/贴纸全部池化 + 上限；`requestAnimationFrame` 里做对象复用，不 new |
| 帧率塌方 | 监测 1s 平均帧耗时，> 33ms 连续 3 秒 → 自动降低粒子上限与数量 |
| WS 断线 | overlay 指数退避重连（1s→2s→4s…最多 10s），重连后拉一次全量状态补齐 |
| 页面跑飞 | overlay 内置看门狗：心跳 30s 无消息则自动 `location.reload()`；也可由后端 `/api/health` 远程触发 |
| 长时间运行 | 每 6 小时定时软刷新一次（无人直播可接受一次 1s 黑屏，远好于卡死） |

### 13.3 无人场景能力对照

| 场景 | 需要的能力 | 本轮/后续 |
|---|---|---|
| 挂机盲盒/云推币机 | 推币机状态机 + 中奖 TTS + 全屏彩蛋 | P1.5 |
| AI 虚拟柜姐 | TTS（逼真音色）+ 商品素材轮播 + 关键词触发的讲解切歌 | 素材层 P1，语音 P1（云音色） |
| 弹幕宝箱 / 券雨 | 能量条状态机 + 全屏雨特效 + 点对点弹窗 | P1.5 |
| 深夜木鱼/助眠 | 极简常驻画面 + 飘字 + 天气/音轨切换 | P1.5（成本最低，建议第一个做） |
| 防止「非实时」判定 | 所有画面由实时事件驱动，禁止纯录播轮播 | 设计约束：循环内容必须至少被事件插断或叠加 |

**反录播硬约束**：任何循环播放的内容（商品视频、背景动画），必须挂一个 30~90s 随机微扰（镜头轻微缩放/色温/贴纸位置），或者必须被弹幕事件打断——纯静帧循环是最容易被判「非实时」的形态。

### 14.2 模块与规则的对应关系

- **模块 = 能力开关**：关掉 `fx_fireworks`，规则里引用它的动作直接跳过并记 trace，不报错。
- **模块 = 参数容器**：每个模块带自己的 `params`（时长、音量、音色、URL），规则动作可覆盖之。
- **模块 = 一键测试**：每个模块在功能中心带「试一下」按钮，不写规则也能验证设备/接口是否通。

接口：`GET /api/modules`（分类+模块+参数+启用态）、`POST /api/modules/toggle`、`POST /api/modules/params`、`POST /api/modules/test/{id}`。
落盘：`data/modules.json`，与 `rules.json` 分离——换规则包不影响开关状态。

## 15. 玩法库与「场景（Scene）」内核

### 15.1 先说结论：所有玩法都是同一个内核

毒舌星座、内鬼测谎、生物进化、资本家模拟器、AI 辩论、NPC 套话——拆开看结构完全一致：

```
输入（弹幕/礼物）
   ↓
Go：状态账本（谁是玩家、谁有秘密、好感度、血量、能量、轮次）
   ↓
LLM：按角色人设 + 当前状态生成台词（带情感标签）
   ↓
Vue：把台词与状态渲染成画面（角色、波形、粒子、榜单）
```

所以不写六个玩法，写**一个场景内核 + 六份配置/剧本**。

### 15.2 内核接口

```go
type Scene interface {
    ID() string
    Init(cfg SceneConfig) error
    OnEvent(ev Event) []SceneCmd   // 弹幕/礼物 → 状态变更与指令
    Tick(now int64) []SceneCmd     // 定时推进（轮次、CD、结案）
    Snapshot() any                 // 全量状态，给前端重连补齐
    Reset() error
}
```

- `SceneCmd` 与现有 `EffectCmd` 共用广播通道（`kind:"scene"`），前端只认指令，不认玩法。
- 状态落 `data/scene_<id>.json`，**重启不丢局**（无人直播核心需求）。
- 每个 Scene 自带 `prompts`（角色人设、规则约束、输出格式 `[情感]正文`），LLM 只做「台词生成」，判定权留给 Go（避免模型乱改数值）。
- 礼物只改变**状态量**（好感、道具、能量），不直接给答案——这是防「刷钱秒通关」的关键。

### 15.3 玩法清单

| 玩法 | 输入 | Go 状态 | 变现点 | 难点 | 优先级 |
|---|---|---|---|---|---|
| 毒舌星座判官 | `星座+场景` 弹幕 | 每人命中记录、雷击/牌子、改命次数 | 转运神符「逆天改命」二次消费 | 毒舌尺度合规；LLM 延迟 | **P1（最省事，复用 80%）** |
| 全员内鬼/测谎局 | `@嫌疑人 提问` | 4 个 AI 的记忆、秘密分层、好感、线索解锁度 | 自白剂/搜查令 | 防提示词注入；状态机最重 | P2 |
| 生物进化斗蛊 | `我是一只会飞的哈士奇` | 生物属性、天灾轮次、存活名单 | 天灾礼物 | 数值平衡；判定叙事一致性 | P2 |
| 资本家割韭菜 | `入职/摸鱼` + 礼物 | 员工数、股价、怒气值、老板台词队列 | 罢工/举报大额触发 | 敏感隐喻，建议弱化「劳动局」类表述 | P2 |
| AI 双人对线 | 弹幕出题 | 两个角色的话术轮次、血量 | 送武器/加血 | 脏话与方言违规 | P1.5 |
| NPC 套话解密 | 弹幕拷问 | 秘密分层、警戒值、道具 | 吐真剂 | 记忆与防注入 | P2 |

### 15.4 选哪个先做

先做**毒舌星座**：它只需要一次 LLM 调用 + 一次 TTS + 一个雷击特效，现有链路直接能跑，一晚就能上线验证流量反应；跑通后再把「状态账本」加厚，升级成内鬼局——那才是留存杀器，但它要的是轮次、记忆、解锁度三套状态，急不来。

**合规红线（所有玩法通用）**：不出现真实人物与品牌、不做地域/性别/疾病歧视、不搞「脏话方言」擦边、不诱导未成年人消费。毒舌可以刻薄，但不能人身攻击到「造黄谣/辱骂外貌」的程度，那句 Prompt 里必须写死禁止项。

## 16. 交互约定：改完即存，没有保存按钮

面向小白主播，「保存」是一个多余动作，也是一处容易忘的坑。控制台全部采用**自动保存**：

| 页面 | 落点 | 触发方式 |
|---|---|---|
| 规则（含启停/新增/编辑/删除） | `rules.json` | `watch(local, deep)` + 800ms 防抖 |
| 进场欢迎门槛 | `config.json` 的 `welcome` | `watch(welcome, deep)` + 700ms 防抖 |
| 礼物库（含批量导入） | `gifts.json` | 800ms 防抖；导入解析完立即写一次 |
| 产品库 | `products.json` | 800ms 防抖 |
| 设置（三页签） | `config.json` 整份 | 1200ms 防抖；字段映射 JSON 解析失败时**不写盘**，只在页面提示 |

设计约束：

1. 首次加载不触发保存——否则一进页面就会把默认值覆盖磁盘；
2. 保存接口是**整份覆盖**（`POST /api/config` 等），所以必须先把磁盘最新内容读回来再改目标字段，不能只提交局部；
3. 新建类弹窗（如规则）在「确定」后才写入列表，取消不落盘，避免半成品被自动保存；
4. 唯一保留的「保存」在观众画像的备注弹窗——那是写一条备注的明确动作，不是配置同步。
